> 适用版本：LizzieYzy 2.5.3 重建版（yzy2.5.3，2023-06 源码）
> 本文只讲"如何修"：先给出每个功能的现有实现与失效原因，再给出可落地的修改方案、
> 代码改动点和需要的数据（抓包）。
> 相关代码集中在 `OnlineDialog.java`、`FoxKifuDownload.java`、`GetFoxRequest.java`、
> `BrowserFrame.java`、`Menu.java`。

## 1. 弈客直播

### 1.1 现有实现（代码证据）

1. 入口（`Menu.java` 3956–3982、`BottomToolbar`）：
   ```java
   Lizzie.frame.bowser("https://home.yikeweiqi.com/#/live", "弈客直播", true);
   ```
   → `BrowserFrame`（JCEF 内嵌 Chromium，`jcef-bundle\`）。

2. 粘贴链接同步（`OnlineDialog.checkUrl()`）：
   - 模式 `https://…/live/room/18328/1/15630642` →
     `https://api.<域名>/golive/dtl?id=18328&flag=1`
   - 模式 `https://…/live/xxx/<id>` → `https://api.<域名>/golive/dtl?id=<id>`
   - 对局室：`https://…/game/xxx/<id>`、`room=<id>&hall…` → 同上

3. 实时对局（`OnlineDialog.req2()`，常量 `c1`）：
   ```java
   https://rtgame.yikeweiqi.com      // socket.io 服务
   ```
   事件链：`login`(hall/room/token/user_id/platform) → `entry_room` → `channel(chat_1_<room>)`；
   收到 `game_info` 后直接取 `sgf`、`boardSize`、`komi`、`blackName/whiteName`、`status`、`resultDesc`。

### 1.2 失效原因

- `api.yikeweiqi.com/golive/dtl?id=…` 实测返回 **HTTP 500（ThinkPHP 错误页）** → 旧 HTTP 接口已下线/迁移；
- `home.yikeweiqi.com` 为 SPA，老版 JCEF 对现代 JS/WebSocket 兼容性差，容易白屏或进不去房间；
- socket.io 的 `login` 可能要求新的 token/访客机制（原代码 `token=-1`、`user_id` 为空）。

### 1.3 修复方案（推荐 A）

**方案 A：直接对接 socket.io 实时房间协议（不依赖浏览器页面）**

1. 解析房间链接（新分享形态）：从 URL 取 `room`（以及可能的 `hall`/`table`）参数；
2. 连接 `https://rtgame.yikeweiqi.com`（socket.io v1 客户端，工程内已有 `io.socket` 依赖）；
3. 发送 `login`（必要时带访客 token/user_id，按抓包确定）→ `entry_room` → 监听 `channel`/`chat_1_<room>`；
4. 收到 `game_info` 后：
   - `info.sgf` → `SGFParser.parseSgf(...)` → `Lizzie.board.getHistory().sync(...)` 载入；
   - 监听后续落子/结果事件，做**增量同步**（只在手数变化时追加，避免整盘重载）；
   - `status==3` 时在评论显示 `resultDesc`（已有逻辑）。
5. 代码改动点：
   - `OnlineDialog.checkUrl()`：新增/替换房间链接正则（按实际分享链接格式）；
   - `OnlineDialog.req2()/login()/entry()/channel()`：按抓包调整事件名与字段；
   - 保留 `initData(JSONObject)`（已能把 `game_info` 转棋盘），重点是把数据源接通。

**方案 B：继续用 HTTP 轮询接口**

1. 抓当前直播页 Network，找到返回房间数据（含 `sgf`/`moves`/`players`/`status`）的 JSON 接口；
2. 替换 `checkUrl()` 中的 `api.<域名>/golive/dtl` 构造；
3. `refresh()`/`parseSgf()` 的解析字段适配新 JSON；
4. 保留"每 N 秒轮询 + 对比手数增量同步"的结构（`syncLiveBoardStat` 已有）。

**方案 C（兜底）**：JCEF 浏览器打开直播页，用户手动复制 SGF 或对局链接导入；不做自动同步。

### 1.4 验收

- 粘贴一个弈客直播链接 → 自动显示双方/贴目/当前手数；
- 直播落子后 ≤2 秒棋盘更新，且不会重复加载整盘；
- 对局结束后评论显示结果。

## 2. 弈客大厅

### 2.1 现有实现

- 菜单「弈客大厅」→ `bowser("https://home.yikeweiqi.com/#/game", …)`（JCEF 浏览器）；
- 进入对局室依赖页面里的链接 + `OnlineDialog` 的 URL 解析（同上）；
- 有开关 `openHtmlOnLive`（「允许弈客直播/大厅进入对局室」）。

### 2.2 失效原因

- 大厅页是 SPA，列表/房间由 JS 动态加载，老 JCEF 兼容性差；
- 即便打开页面，进入对局室仍走 §1 中已失效的 `golive/dtl`。

### 2.3 修复方案

1. **JCEF 升级/配置**（让页面能正常显示）：
   - 升级 `jcef-bundle` 到较新版本（现有 jcef 约 212MB，版本偏旧）；
   - 打开 `windowless_rendering_enabled=false`（已如此）+ 允许第三方 Cookie、持久化用户数据目录；
   - 必要时设置移动端 UA，很多棋类站点对桌面 UA 有差异；
2. **大厅 → 对局室**：
   - 方案 1：解析大厅页面对局室链接（DOM/`cefQuery` 注入 JS 读取），拿到 room id 后走 §1 的 socket.io；
   - 方案 2（更稳）：抓大厅 API（房间列表 JSON），在本地做"大厅列表"窗口，点击进入 → 直接 socket.io；
3. 保留 `openHtmlOnLive` 开关语义（是否允许从网页进入对局室）。

### 2.4 验收

- 菜单「弈客大厅」能正常显示房间列表（或网页可操作）；
- 点击一个对局室 → 棋盘载入并实时同步，与直播一致。

## 3. 腾讯棋谱

> 注意：腾讯围棋（原"腾讯欢乐围棋"）与野狐同属腾讯，账号体系已逐步整合。
> 代码里"野狐(腾讯)棋谱"是同一个入口（`Menu.foxKifu`）。

### 3.1 现有实现（代码证据，常量均已解码）

| 常量 | 解码值 | 用途 |
|---|---|---|
| `b`（`OnlineDialog` 111 行） | `wss://hlws.huanle.qq.com/wqbroadcastlotus` | 分享链接（gameid+createtime）的二进制 WebSocket 协议 |
| `b2` | `ws://wshall.huanle.qq.com/NewEagleEyeLotus` | 旧直播广播 WS |
| `b3`（120 行） | `https://weiqi.qq.com/openqipu/getqipu?callback=jQuery1&gamecode=` | 腾讯棋谱 JSONP 接口 |
| `b4` | `huanle.qq.com` | type 4 直播请求 host |

`OnlineDialog.checkUrl()`：
- type 3：URL 带 `gameid` + `createtime` → `req()`（`req1()` 构造二进制帧，msgID=23406 等）；
- type 4：URL 带 `gametag` + `uin` → `http://wshall.huanle.qq.com/wxnseed/Broadcast/RequestBroadcast?…`。

### 3.2 失效原因

- `huanle.qq.com` / `weiqi.qq.com` 是 2017 年前后"腾讯欢乐围棋"的接口域，早已迁移；
- 二进制 WS 协议（`req1()` 里逐字节构造）无文档、随客户端版本变化，维护成本极高。

### 3.3 修复方案

1. **首选：腾讯围棋棋谱统一走野狐新数据**（腾讯围棋=野狐）。即"腾讯棋谱"入口直接复用 §4 的"野狐分享链接导入"：
   - 解析 `chessid` / 分享链接 → 请求野狐分享页 JSON → SGF → 载入；
   - 代码上：`Menu.foxKifu` → 新的 `FoxKifuDownload`（链接导入版），删除/停用 `b/b3` 旧协议分支。
2. 如果必须支持腾讯围棋独立棋谱页：
   - 抓 `https://weiqi.qq.com/…` 现行"棋谱详情"请求（JSON/JSONP），拿到落子/SGF；
   - 替换 `b3` 的 JSONP 调用与 `parseSgf` 的字段映射；
   - 分享链接解析（`gameid/showtype/showid/chessid/createtime`）保留，但改走新接口。
3. 不建议继续逆向 `hlws.huanle.qq.com` 二进制协议（易失效、成本高）。

### 3.4 验收

- 粘贴腾讯围棋分享链接 / 野狐分享链接 → 能载入棋谱；
- 棋谱手数、贴目、黑白名正确。

## 4. 野狐棋谱

### 4.1 现有实现（代码证据）

- 入口：菜单「野狐(腾讯)棋谱」→ `Lizzie.frame.openFoxReq()` → `FoxKifuDownload` 窗口；
- 数据来源：`GetFoxRequest` 启动外部程序
  ```
  jre\java17\bin\java.exe -jar foxReq\FoxRequest.jar
  ```
  （jar 由 `Utils.copyFoxReq()` 从 `assets/foxReq/FoxRequest.jar` 解出），
  通过 stdin 发命令：`user_name <名>`、`uid <uid> [lastCode]`、`chessid <id>`；
- 反编译该 helper 可见它请求：
  ```
  https://happyapp.huanle.qq.com/cgi-bin/CommonMobileCGI/TXWQFetchChessList?type=4&username=…
  http://happyapp.huanle.qq.com/…&lastCode=…&uid=…&RelationTag=0
  ```
  → 腾讯欢乐围棋时代的 CGI，早已停用。

### 4.2 现行可用入口（已实测）

- 野狐官网棋谱列表：`https://www.foxwq.com/qipu.html`（"大赛棋谱"，含 100 盘）；
- 现分享链接格式：
  ```
  https://h5.foxwq.com/yehunewshare/?chessid=<长数字ID>&title=<URL编码标题>&boardsize=19
  ```
- 分享页是 SPA（直接抓 HTML 只有 "H5"），棋谱数据由 JS 再请求接口 → **需要抓包确认接口**。

### 4.3 修复方案（推荐 A：链接导入）

1. `FoxKifuDownload` 增加输入框"粘贴野狐分享链接"；
2. 解析 `chessid`（正则 `h5\.foxwq\.com/yehunewshare/.*chessid=(\d+)`）；
3. 新增 `FoxKifuClient`（`HttpURLConnection`，带 `Referer`/`User-Agent`）：
   - 请求分享页对应 JSON（抓包确定 URL 与参数）；
   - 解析出落子列表（或直接拿到 SGF/手数），转成 SGF 字符串；
4. `SGFParser.loadFromString(sgf)` 载入 → `Lizzie.board.setMovelistAll()` → 自动分析；
5. 错误处理：接口失败时提示"请更新抓包接口"并给出复制链接的兜底。

**方案 B：大赛棋谱列表**

1. 抓取 `www.foxwq.com/qipu.html`（服务端渲染，结构稳定）：
   - 每行 `<a href="https://h5.foxwq.com/yehunewshare/?chessid=…&title=…">标题</a>`；
2. 在 `FoxKifuDownload` 里显示列表（几十/上百条），点击 → 走方案 A 的 chessid 导入；
3. 优点：不需登录，实时性够用（官网每日更新）。

**方案 C：按用户名下载（旧主功能）**

需要野狐客户端登录协议（TCP/WS、账号鉴权、棋谱列表/详情命令）；
旧 helper 用的 CGI 已死，重写成本高、易被封 → **建议一期不做**，用 A/B 替代。

### 4.4 验收

- 粘贴野狐分享链接 → 自动载入棋谱（手数/贴目/黑白名正确）；
- 从大赛棋谱列表点选 → 同上；
- 失败时有明确提示。

## 5. 通用实施步骤（按顺序）

1. **抓包**（见 §6）：四类页面各抓一份请求/响应；
2. **先做野狐棋谱**（最简单、风险最低）：新增 `FoxKifuClient` + `FoxKifuDownload` 链接导入；
3. **再做弈客直播**：socket.io 协议接通（或替换 HTTP 接口）；
4. **然后弈客大厅**：升级 JCEF + 大厅列表/对局室链接；
5. **最后腾讯棋谱**：优先复用野狐数据；确需独立支持时再抓腾讯现行接口；
6. 每完成一项：`mvn package`（`-Dmaven.compiler.release=8 -Dfmt.skip=true`）→ 替换 jar → smoke 测试 → 自测链接。

### 代码改动清单

| 文件 | 改动 |
|---|---|
| `OnlineDialog.java` | `checkUrl()` 新增/替换链接正则；`refresh()`/`parseSgf()` 适配新 JSON；`req2()/login()/entry()/channel()` 按新协议调整 |
| `FoxKifuDownload.java` | 增加"粘贴链接"输入框；数据源改为 `FoxKifuClient`；保留/移除用户名下载 |

## 6. 抓包清单（每项需要什么）

| 功能 | 需要抓的请求 | 关键字段 |
|---|---|---|
| 弈客直播 | `home.yikeweiqi.com/#/live/room/...` 页面的 Network（Fetch/XHR + WS） | 房间/对局数据 JSON（sgf、moves、boardSize、komi、players、status）；socket.io 连接 URL、事件名、login 参数 |
| 弈客大厅 | `home.yikeweiqi.com/#/game` 列表与进入对局室 | 房间列表 JSON；对局室 id/参数；进入后房间数据 |
| 腾讯棋谱 | `weiqi.qq.com` 棋谱详情页 / 分享链接打开过程 | 棋谱 JSON/JSONP（SGF 或落子列表）、code/参数 |
| 野狐棋谱 | `h5.foxwq.com/yehunewshare/?chessid=…` 页面 | 加载棋谱数据的 JSON 请求（URL + 参数 + 响应结构） |

抓包方法：Chrome/Edge → F12 → Network → 勾选 Preserve log/Disable cache → 刷新页面 → 过滤 Fetch/XHR（或 WS）
→ 右键请求 Copy as cURL 或 Export HAR（详见包内 `文档\抓包指南.md`）。

## 7. 风险与注意事项

1. 第三方接口随时可能变更；建议把 URL/字段集中到常量类，方便快速替换；
2. 不要做账号登录模拟（易触发风控）；优先匿名访客/分享链接；
3. JCEF 升级涉及 `jcef-bundle` 与 Java 依赖（`jcef` 版本），升级后需整体回归启动/显示；
4. 直播增量同步要按"手数"去重，避免整盘重载导致卡顿；
5. 所有改动只影响对应功能，需回归：程序启动、引擎分析、形势判断、保存/加载 SGF。

## 8. 【已修复】野狐 / 腾讯棋谱（本版）

### 8.1 新实现（已验证）

旧路径 `FoxKifuDownload → foxReq/FoxRequest.jar → happyapp.huanle.qq.com/...TXWQFetchChessList`
已停用。新实现改为直接调用野狐现行接口：

**棋谱列表**
```
https://www.foxwq.com/qipu.html            （第 1 页）
https://www.foxwq.com/qipu/index/p/N.html  （第 N 页）
```
服务端渲染，直接正则解析每盘标题 / chessid / 时间。

**棋谱数据**（从分享页 JS 中定位到的真实接口）
```
https://h5.foxwq.com/yehuDiamond/chessbook_local/YHWQFetchChess?chessid=<id>
```
返回 JSON：
```json
{"result":0,"chessid":"…","flag":6,"chess":"(;GM[1]FF[4]SZ[19]…"}
```
`chess` 字段即 SGF（含野狐的嵌套变化图），客户端会：
1. 提取 JSON 字符串字段（处理 `\"`、`\\`、`\uXXXX` 等转义）；
2. 自动处理 gzip；
3. 中文兼容：UTF-8 解码出现替换字符时自动改用 GB18030/GBK；
4. 提取 `(;` 起始的 SGF 交给 `SGFParser.loadFromString()` 载入。

### 8.2 新增代码

| 文件 | 说明 |
|---|---|
| `analysis/FoxKifuClient.java` | 列表解析、chessid 解析、SGF 下载（JSON/gzip/GBK） |
| `gui/FoxKifuImport.java` | 新导入窗口：粘贴链接/chessid 导入 + 「刷新大赛棋谱列表」双击导入 |
| `Menu.java` / `BottomToolbar.java` | 「野狐(腾讯)棋谱」入口改为打开新导入窗口 |

### 8.3 测试结果

- 本地 mock HTTP 服务端到端测试：**14/14 通过**
  （列表解析、chessid 解析、SGF 明文/gzip/JSON 包裹、GBK 中文、404 异常）；
- **真实接口测试通过**：
  - 真实列表：抓取到 20 盘（标题/日期/chessid 正确）；
  - 真实棋谱：`YHWQFetchChess` 返回 SGF，长度 **46,258** 字符，`(;GM[1]…SZ[19]` 校验通过。

### 8.4 使用方法

菜单「直播 → 野狐(腾讯)棋谱」→ 打开导入窗口：
1. 粘贴分享链接（`h5.foxwq.com/yehunewshare/?chessid=…` 或旧 `share.foxwq.com/…chessid=…`）
   或直接填 chessid → 点「导入链接」；
2. 或点「刷新大赛棋谱列表」→ 双击任意一盘导入；
3. 载入后自动回到主棋盘并开始分析。

### 8.5 腾讯棋谱说明

腾讯围棋与野狐为同一体系：腾讯分享链接里通常也带 `chessid`，
因此本客户端同样可解析腾讯分享链接（`parseChessId` 兼容 `chessid=` 参数），
即"腾讯棋谱"入口统一走野狐数据。
### 8.6 昵称搜索（恢复"输入昵称即可搜索棋谱"）

官网棋谱页自带服务端搜索（标题/棋手名），直接复用：

```
第 1 页：https://www.foxwq.com/qipu.html?keyword=<URL编码的昵称>
第 N 页：https://www.foxwq.com/qipu/index/keywords/<URL编码的昵称>/p/N.html
```

- 页面中 `共 X 盘` 即总盘数；
- 每页 20 盘，正则提取 `<a href="https://h5.foxwq.com/yehunewshare/?chessid=...">标题</a>` 与时间；
- 实测：`keyword=柯洁` → 共 100 盘，标题含棋手名，双击任意一盘即可用 `YHWQFetchChess` 载入。

窗口（`FoxKifuImport`）现在的布局：
1. 第一行「昵称/关键字」+「搜索棋谱」+「下一页」；
2. 第二行「分享链接/chessid」+「导入链接」；
3. 中间结果列表（双击载入）；
4. 底部「大赛棋谱列表」与状态栏（显示总盘数/页码）。
### 8.7 昵称搜索的范围（重要）

官网棋谱搜索（`qipu.html?keyword=`）只索引**公开/大赛棋谱**，**不包含普通网棋**。

实测例子（用户提供的一盘网棋）：
```
http://h5.foxwq.com/yehunewshare/?chessid=1784893976010001495&boardsize=19&...
标题：野狐围棋 网棋棋谱 | 野狐最菜ai[9段] VS 武灵儿[9段]
```
- 昵称搜索 `野狐最菜ai` / `武灵儿` → **共 0 盘**（搜不到）；
- 直接 `chessid=1784893976010001495` → **SGF 下载成功**（591 字符，让4子，W+R），可正常载入。

因此：
1. **普通网棋**：把分享链接粘贴到「昵称/关键字」框或第二行「分享链接」框 → 直接导入；
2. **大赛棋谱/公开棋谱**：用昵称搜索（如 `柯洁` → 共 100 盘），或「大赛棋谱列表」。

界面已做两处适配：
- 昵称框里粘贴的若是链接/chessid，会自动识别并直接导入（无需再输入昵称）；
- 搜索结果为 0 时提示"官网搜索仅含公开/大赛棋谱；普通网棋请用分享链接导入"。

### 9.1 关键发现（实测）


  实测房间 18328：返回 9,924 字节、SGF 正常解析。

### 9.2 原代码的两个 Bug

1. **host 拼错**：`checkUrl()` 用 `"https://api." + 域名` 生成请求，
   对 `home.yikeweiqi.com` 会拼成 `api.home.yikeweiqi.com`（不存在）；
   已改为：弈客域名 → `api.yikeweiqi.com`。
2. **数据通道用错**：type 1/5（直播间、对局室）原来走 `req2()`（socket.io），已失效；
   现在改为 **HTTP 轮询**。

### 9.3 新实现（YikeLiveClient + OnlineDialog）

| 文件 | 内容 |
|---|---|
| `analysis/YikeLiveClient.java`（新增） | `liveUrl(roomId)`、`fetch(url)`：带 UA/Referer/Accept、gzip、UTF-8→GBK |
| `OnlineDialog.java` | `apiHost()` 修正域名；type 1/5 → `startYikePoll()`：首次拉取 + 每 `refreshTime` 秒轮询；`parseSgf()` 直接处理 JSON（`Result.live.Content`），自动同步手数/解说/结果 |

### 9.4 使用方法

1. 菜单「文件 → 打开在线链接」；
2. 粘贴弈客直播/对局室链接（如 `https://home.yikeweiqi.com/#/live/room/18328/1/…`
   或 `live/board/<id>`、`game/…/<id>`）；
3. 程序会拉取当前局面 SGF，并每 `刷新时间` 秒自动更新（可在对话框里改刷新间隔）；
4. 弈客大厅：菜单「直播 → 弈客大厅」打开网页浏览；进入某个对局室后，把地址栏链接

### 9.5 关于你给的 `move.json`

该文件是**弈客 AI 分析接口**（`ai.yikeweiqi.com`）的单点分析结果，字段含义：
`move`（手数）、`stone`（坐标）、`b_rate/w_rate`（胜率）、`children[]`（候选点，
含 `pnv/po/nodes/an_result`）、`mark:"首选"` 等。
它**不是直播/对局数据**，不能用来同步棋盘；但可用于"AI 候选点/胜率展示"。
若需要，可后续实现"粘贴弈客分析 JSON → 在棋盘上显示候选点/胜率"。
### 9.6 新直播链接格式支持（本版修复"还是打不开"）

用户实际用的链接是**新格式**：

```
https://home.yikeweiqi.com/#/live/new-room/197418/0/0
```

原 `checkUrl()` 的正则 `live/[a-zA-Z]+/([^/]+)/[0-9]+/([^/]+)` 中 `[a-zA-Z]+`
匹配不了 `new-room` 里的 `-` → 解析失败 → 走了"直接把 URL 当 SGF"的分支 → **空盘**。

修复：
- `YikeLiveClient.parseRoomId(url)` 支持
  `#/live/new-room/<id>/<hall>/<room>`、`#/live/room/<id>/<n>/<seq>`、`#/live/board/<id>`；
- `YikeLiveClient.ajaxUrlFor(url)` → `https://api.yikeweiqi.com/golive/dtl?id=<id>&flag=1`；
- `OnlineDialog` 新增 type 6：这类链接直接走 HTTP 轮询（同 §9.3）。

实测该接口返回（房间 197418）：

```json
{"Status":1200,"Result":{"live":{"Content":"(;GM[1]…;B[ek])","HandsCount":"29",
 "BlackPlayer":"…","WhitePlayer":"…","GameName":"第1届韩国水协银行杯…"}}}
```

即 **29 手完整局面**，可正常载入。

> 另：`move (1).json` 来自 `hawkeye.yikeweiqi.com/api/report/live/move?token=…&num=18`，
> 是**天眼 AI 对第 18 手的单点分析**（候选点/胜率），不是棋盘局面数据；
> 局面数据用上面的 `golive/dtl` 即可。
### 9.7 请求头对齐（按 F12 抓到的 headers）

按用户提供的 hawkeye 请求头，`YikeLiveClient` 现在发送完整浏览器头：

```
User-Agent: Chrome/132
Accept: application/json, text/plain, */*
Accept-Language: zh-CN,zh;q=0.9
Accept-Encoding: gzip, deflate
Origin: https://home.yikeweiqi.com
Referer: https://home.yikeweiqi.com/
Cache-Control: no-cache
Pragma: no-cache
```

并支持 **gzip / deflate** 两种压缩的自动解压；UTF-8 解码异常时回退 GB18030。

另外：接口返回里没有 `Content`（房间未开始/无数据）时，不再用空数据覆盖棋盘。

### 9.8 hawkeye 接口说明

| 接口 | 用途 | 实测 |
|---|---|---|
| `https://hawkeye.yikeweiqi.com/api/report/live/move?token=<token>&num=<N>` | 第 N 手的**天眼 AI 分析**（胜率/候选点/pnv） | 200，返回 `stone/b_rate/w_rate/children[]` |
| `.../api/report/live/info?token=<token>` | 局面列表（hands） | 返回 `hands:null`（当前 token 不暴露棋谱） |

token 是按直播场次下发的（页面运行时获得，不在分享链接里），
因此**局面同步仍用 `api.yikeweiqi.com/golive/dtl`**（含 `Content` SGF + `HandsCount`），
hawkeye 的 `move` 接口只适合做 AI 分析展示。

### 10.4 实时同步（本版新增）

新增 `gui/YikeGameSync.java`：大厅里双击一局后**自动进入实时同步**——

- 每 **3 秒**（`-Dlizzie.yike.syncInterval=3` 可调）拉一次 `game/info`；
- 比较 `hands_count`：**只有手数增加时才重载**，所以对方一落子，棋盘自动跟一步；
- 同步中对话框显示"实时同步中：黑 vs 白（N 手）"，点「停止同步」可退出；
- 「文件 → 打开在线链接」粘贴 `game/play/<hall>/<id>` 链接时，同样会按刷新间隔自动跟随（且手数不变时不再重复重载）。

说明：同步采用"重载最新 SGF"的方式，会自动跳到最新一手（适合观看直播）；
如果你正在回看历史手，下一步落子时会跳回最新。
### 10.5 token 配置（代码中不含任何 token）

从本版起，代码**不再内置任何弈客 token**（避免泄露）。使用大厅前请配置：

1. 在程序目录新建 `yike-token.txt`，内容为 F12 抓到的 `Authorization: Bearer` 后面的 token；
2. 或在 `config.txt` 的 `ui` 下加：`"yike-game-token": "<token>"`；
3. 或启动参数：`-Dlizzie.yike.token=<token>`。

未配置时「弈客大厅」会提示"未配置弈客 token"。token 获取方法：
打开任意对局页 → F12 → Network → 找 `game-server.yikeweiqi.com/game/info?id=...`
→ 请求头 `authorization: Bearer xxx` → 复制 xxx。
